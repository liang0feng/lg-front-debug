灵基 API 简明调用流程

本地 HMAC 签名 → 换取 AccessToken → Bearer 调用业务

1 明确流程2 导入与配置3 获取 AccessToken4 调用业务

1 明确流程

HMAC 是本地签名算法，不需要先请求一个“HMAC 接口”。第一个 HTTP 请求就是携带 HMAC 签名的令牌签发请求；服务端验签后返回 AccessToken。

共 15 个接口：1 个签发接口 + 14 个 Bearer 业务接口。

2 导入与配置

  1. 在 Apifox 新建测试项目，导入 lingee-openapi-v2.yaml。只导入这一个 YAML。
  2. 环境前置 URL 设置为真实服务源站，例如 https://your-host，不能带 /work 或 /console。
  3. 填写下表变量；停用旧项目级 HMAC 脚本、旧继承认证及重复全局头。
环境变量填写内容
lingee_app_id应用 ID
lingee_app_secret应用 Secret，仅填写本地私密值
lingee_tenant_id应用绑定租户，如 2559609318685252608_production
lingee_proxy_modeFIXED_PROXY 或 HEADER_USER，按实际应用配置
lingee_access_token初始留空，由后置脚本保存

3 获取 AccessToken

  1. 打开“01 认证 换取 AccessToken”，Auth 选 No Auth；签名通过显式请求头完成。
  2. Body 选 raw JSON，固定用户只保留 tenant_id；白名单用户增加 subject_type 与 subject。
  3. 从详细手册复制“签发前置脚本”和“保存令牌后置脚本”，仅粘贴到该接口。
  4. 发送请求，确认返回 data.access_token，当前环境变量被更新。

4 调用业务

  1. 先测试 GET /work/openapi/v1/skills，无需请求体。
  2. Auth 选择 Bearer Token，值填 {{lingee_access_token}}，不要再写 Bearer 前缀。
  3. Header：X-Tenant-Id 填 {{lingee_tenant_id}}；不得携带任何 X-Lingee-OpenApi-* 头。
  4. 令牌有效期 2 小时；过期后重复签发。切换租户或代理用户后也应重新签发。

YAML 不会自动安装脚本或串联调用。签发与技能列表可作为第一轮鉴权联调；会话等业务写接口还需要补齐真实请求字段。
