# 灵基对话台 v1.0 · 设计说明

> 目标：在 v0.9.1 单文件调试版上，把「流式通道、会话模型、资源加载、渲染、移动端、视觉」六处结构性欠账一次性补齐，并保持零依赖、单进程、本机运行。

## 0. 一句话结论

**每个会话一条常驻 SSE 通道 + 一个按会话隔离的轮次（turn）注册表**。SSE 负责实时可读性，轮询只在「SSE 没动静 / 断线 / 终态缺失」时启动，作为终态兜底。界面只渲染「当前会话」，但所有会话的轮次都在后台独立推进。

## 2. 通道：SSE 优先，轮询兜底

### 2.1 为什么不能用 EventSource

`EventSource` 不能带 `Authorization` 头。因此用 `fetch` + `ReadableStream` 手工读流：

```
GET /work/openapi/v1/session/{sid}/event?event_id={token}
Authorization: Bearer ...   Accept: text/event-stream
```

解析器按 `\n\n` 切事件块，支持多行 `data:`、CRLF、BOM、注释行（`:` 开头）、`event:` 与 `retry:` 忽略。事件类别只看 JSON 的 `type` 字段（官方规范：不依赖 SSE 的 `event:` 行）。

### 2.2 通道生命周期

| 状态 | 触发 | 行为 |
|---|---|---|
| `idle` | 会话未打开 | 不建连 |
| `connecting` | `ensureChannel(sid)` | 建连，等待 `server.connected`（上限 8s） |
| `open` | 收到 `server.connected` | 保持；记录 `lastEventAt` |
| `retrying` | 流结束 / 网络错误 | 指数退避 1s→2s→4s→8s→15s，仍用最初提交的 `event_id` token |
| `closed` | 主动关闭 / 会话被删除 | 停止重连 |

- **心跳看门狗**：45s 无任何事件视为假死，主动断开并重连。
- **通道复用**：同一 `(base, tenant, sid)` 只保留一条；切会话不关连接。
- **LRU 上限**：最多同时保活 6 条通道；超出时关闭最久未使用且无进行中轮次的那条。
- **token 过期**：建连返回 401 时，单飞重签一次再连；仍失败则通道置 `error` 并提示。

### 2.3 发起对话的时序（修正 v0.9.1 的缺陷）

v0.9.1 建 SSE 时带了 `event_id`，但 `POST /chat` **没有带同一个 `event_id`**，服务端会生成新 token，事件可能送不到已建立的连接。v1.0 改为：

```
1. ensureChannel(sid)                → 等到 server.connected
2. POST /chat?event_id={同一 token}   → 校验响应体 code=="0"（202 不代表成功）
3. 收流；同时启动「静默看门狗」
```

关键细节：
- 必须**显式建会话 → 建 SSE → 发对话**，不能依赖「不传 session_id 自动建会话」。
- `202 + code=5001093001`（SSE 路由未注册）视为**可恢复失败**：重连通道后重发对话，最多 2 次。
- `409 + 5001303001`（会话已有运行中任务）→ 提示并可「接管查询」：用该会话已知 `task_id` 走轮询兜底。

### 2.4 轮次状态机

```
submitted ─┬─ SSE 有增量 ──────────────► streaming ─► session.idle ─► done
           ├─ 5s 内 SSE 无任何增量 ────► polling  ─┬─ 终态 ─────────► done
           └─ SSE 断开 ─────────────────► polling  └─ 达上限 ───────► pending（保留 task_id）
```

- **静默看门狗**：提交后 5s 内未收到任何 `message.part.*` / `session.status(busy)`，启动轮询。
- **断线即兜底**：通道进入 `retrying` 且有进行中轮次，立即启动轮询，不等重连。
- **轮询节奏**：优先 `Retry-After`，否则 2s→3s→4.5s→6s→9s→13s→20s，最多 8 次；之后转入 30s 慢轮询，直到 5 分钟仍无终态 → 标记 `pending`。
- **谁先到用谁**：SSE 先产生文本则轮询只补终态字段（artifacts/status），绝不覆盖已有流式文本；轮询先拿到 answer 而 SSE 无文本，则用 answer 收尾。
- **幂等**：`session.idle`、`session.status(idle)`、`session.updated` 都可能重复；以 `turn.finished` 做一次性收尾，重复事件直接忽略。
- **快照优先**：`message.part.updated` 带 `time.end` 时以快照 `text` **覆盖**本地累积值；`message.part.delta` 只追加 `field == "text"` 的部分。
- **reasoning 不混入回答**：`reasoning` 类 part 单独折叠展示，绝不拼进最终答案。

### 2.5 为什么不「并跑」

v0.9.1 提交后无条件轮询 3 次，SSE 正常时白打 3 次接口，SSE 断时额度已耗尽。v1.0 的轮询由**事件驱动**：只有「静默 / 断线 / 无终态」才启动，且与 SSE 共享同一个轮次对象，天然去重。

## 3. 会话模型：历史、切换、并行

### 3.1 按会话隔离

```js
Session = {
  id, title, createdAt, updatedAt,
  messages: [{ id, role, text, reasoning, artifacts, tools, status, time }],
  pendingTask,          // 未完成轮次的 task_id
  channel,              // 该会话专属 SSE 通道
  turn,                 // 该会话当前轮次（可能为空）
  unread,               // 后台完成时的未读标记
  queuePos              // 排队位置（0 表示未排队）
}
```

全局不再有 `S.busy` 一把锁。**锁在会话上，不在应用上。**

### 3.2 切换与会话恢复

- 切换会话**不关闭 SSE、不清空轮次**，只切换渲染目标；后台仍在收流。
- 切回时重绘消息列表，并挂上该会话仍在进行的轮次（含已流出的半截文本）。
- 应用启动时从本地索引恢复全部会话摘要；点开时再加载该会话的消息体。
- `pendingTask` 的会话在列表标「未完成」；点开后提供「继续查询」，且**不自动发起**（避免打开即打接口）。

### 3.3 多会话并行

- 每个会话可同时拥有一个进行中轮次；不同会话互不阻塞。
- **并发上限 3**（可在此调整）：第 4 个会话进入队列，输入区显示「排队中 · 第 N 位」，有空位自动启动。
- 同一会话重复发送 → 直接拦截并提示「该会话正在执行」。
- 429（租户并发上限）→ 自动退避重试一次，再失败则转为排队。

### 3.4 多标签页

- 每个标签页有独立 `tabId`；会话消息按 `lg.sess.v2.<sid>` **分键存储**，不再整包覆盖。
- 索引 `lg.index.v2` 只存摘要；写入时合并而非覆盖。
- 监听 `storage` 事件：其它标签页更新同一会话时，若本页该会话空闲则刷新列表；有进行中轮次时不覆盖本地流式内容。

## 4. 资源缓存：模型 / 工具 / 智能体

### 4.1 问题归因

「token 没过期但列表没选项」有四种成因，必须区分：

1. 请求根本没发（没点刷新 / 获取令牌后未自动加载）；
2. 请求失败（503 数据源不可用、401 token 失效、403 未授权）；
3. 成功但为空（模型接口空数组是**正常状态**）；
4. 结果被错误地写入空值覆盖了旧缓存。

### 4.2 缓存结构

```js
cacheKey = `lg.res.v1.${base}|${tenant}|${appId}|${subject}|${subType}`
{
  models: { items, fetchedAt, source: 'network'|'cache', error: null|{code,message} },
  tools:  { ... },
  agents: { ... },
  schema: 1
}
```

三层：内存 → localStorage → 网络。打开页面先渲染缓存（标注「缓存 · 3 分钟前」），超过 10 分钟才在拿到令牌后自动刷新。

### 4.3 两个操作，语义不同

| 操作 | 语义 |
|---|---|
| **刷新** | 强制走网络。成功且返回空数组 → **接受空结果**并提示「服务端返回 0 项」；失败 → **保留旧缓存**并标注「刷新失败，使用缓存」 |
| **清空缓存** | 删除该环境的缓存（含选择状态），随后自动重新拉取；**以新结果为准**，失败就显示空态与错误，不回退旧数据 |

- 单飞锁：并发点击只发一轮请求。
- 获取令牌成功后自动加载一次。
- 令牌 401 → 重签一次并重试（已有的能力，收口到 api 层）。
- 界面呈现每个资源的「条数 / 来源 / 时间 / 错误」，不再用一句 toast 代替。

## 5. Markdown 渲染

自研渲染器（离线可用，无 CDN），**先转义后排版**，杜绝 XSS：

- 支持：标题、粗体/斜体/删除线、行内代码、围栏代码块（带语言与复制按钮）、有序/无序/嵌套列表、任务列表、引用、表格、分隔线、链接（仅 http/https/mailto）、裸 URL。
- 流式容忍：未闭合的围栏按代码块渲染；渲染节流 80ms，避免长文本抖动。
- 用户消息按纯文本渲染（保留换行），助手消息按 Markdown 渲染。
- 链接统一加 `rel="noopener noreferrer" target="_blank"`；HTML 标签一律转义，不开放原始 HTML。

## 6. 移动端

- `≤900px`：侧栏转为**抽屉**，顶栏出现汉堡按钮；遮罩点击关闭；打开会话后自动收起。
- `≤900px`：连接设置改为**全屏/底部抽屉**；工具选择改为**底部弹层**。
- 输入框 `font-size:16px` 防 iOS 聚焦缩放；底部加 `env(safe-area-inset-bottom)`。
- 顶栏保留关键状态（会话标题、连接状态、菜单）；发送/停止按钮加大触控区。

## 7. 视觉与交互

- 设计令牌化：颜色、间距、圆角、阴影、层级统一；支持浅色/深色（跟随系统 + 手动切换）。
- 消息：头像、角色、时间、流式光标、后台会话未读点、完成/失败/排队状态。
- 代码块：语言标签、复制按钮、横向滚动。
- 滚动：仅在接近底部时自动跟随；离开底部时出现「回到底部」按钮。
- 交互：`Ctrl/⌘+Enter` 发送、`Esc` 关闭浮层、会话搜索、重命名、删除、导出 Markdown/JSON、复制回答。
- 动效遵循 `prefers-reduced-motion`。
- 无障碍：焦点环、`aria-*`、键盘可达、对比度达标。

## 8. 可靠性与错误处理

- 错误分类：网络 / 鉴权 / 参数 / 权限 / 限流 / 服务端 / 业务码；每类给可执行建议。
- 业务码提示表覆盖签发与对话链路（5001093001、5001303001、5001053001、5001143001、5001033010、5001303003 等）。
- 调试看板保留并增强：按会话/类型过滤、搜索、复制 cURL、SSE 事件统计（事件数、首末跨度、逐条/批量判断）、密钥默认打码。
- 令牌单飞：多个会话同时需要令牌时只签一次。
- 关闭页面时把进行中的部分输出与 `task_id` 落盘，下次打开可续查。

## 9. 存储键

| 键 | 内容 |
|---|---|
| `lg.cfg.v2` | 常用配置（presets）+ 当前选中 + 偏好 |
| `lg.index.v2` | 会话摘要索引 |
| `lg.sess.v2.<sid>` | 单会话完整消息 |
| `lg.res.v1.<envKey>` | 资源缓存 |
| `lg.debug.v2` | 调试记录（24h / 200 条） |
| `lg.meta.v2` | tabId、主题、最近会话 |

v0.9.1 的 `lingee.*` 键在首次启动时自动迁移，旧记录不丢。

## 10. 测试与验收

- `node test/selftest.mjs`：SSE 分块解析、Markdown 各类语法与 XSS、存储迁移。
- 手工验收清单：
  1. 建会话 → SSE 就绪 → 提问 → 逐段出现 → idle 收尾；
  2. 断网/杀 SSE → 5s 内自动轮询兜底；
  3. A 会话流式中切到 B 提问 → 两者并行，A 完成时侧栏出现未读点；
  4. 刷新页面 → 历史与未完成轮次可恢复；
  5. 移动端宽度 → 汉堡打开历史、设置抽屉可用；
  6. 令牌有效时刷新资源 → 有缓存提示；清空缓存 → 以新结果为准。
