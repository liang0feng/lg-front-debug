# 灵基对话台（独立 Node 应用）

> **v0.9.2 快速版 · 2026-11-23**　单会话单轮的可用快照，含跨平台启动器与本机数据清除入口。多会话并行、SSE 优先/轮询兜底的通道重构尚未纳入本版，见文末「已知限制」。

一个零依赖的本地 Web 应用：托管前端页面，并把同源 `/api/*` 请求转发到灵基 OpenAPI 环境。
因为页面和接口同源，**不会再遇到 `file://` 打开时的跨域（CORS）问题**。

## 运行

三种方式任选，都会**自动挑空闲端口**（3000 被占用就顺延到 3001、3002…）并尝试自动打开浏览器：

| 平台 | 做法 |
|---|---|
| Windows | 双击 `启动-Windows.bat` |
| macOS / Linux | 终端执行 `./启动-macOS-Linux.sh`（首次需 `chmod +x 启动-macOS-Linux.sh`） |
| 任意平台 | `node start.js` |

> ⚠ `启动-Windows.bat` **故意只写 ASCII 字符**（提示语是英文）。Windows 的 cmd 按字节偏移解析批处理，文件里一旦出现中文，多字节字符会把命令行切碎，出现 `'xxx' 不是内部或外部命令` 这类乱码报错。要改这个文件，请保持纯 ASCII；中文提示交给 `start.js` 输出。

启动后控制台会打印实际地址，例如 `http://127.0.0.1:3001`。

也可以指定起始端口：`node start.js 8080`。

如果不想自动开浏览器，加环境变量 `NO_OPEN=1`。

只想用最朴素的启动方式（不选端口、不开浏览器）：

```bash
node server.js
```

此时端口被占用会直接报错退出，需要手动换：`PORT=8080 node server.js`（Windows PowerShell：`$env:PORT="8080"; node server.js`）。

转发目标默认是 `https://app.lingee.com`，也可以在页面里覆盖：

```bash
TARGET=https://other-host node start.js
```

## 首次使用

1. 点左下角「连接设置」。
2. 填服务地址（例如 `https://app.lingee.com`，只到域名，不带 `/work` 或 `/console`）、App ID、App Secret、租户 Tenant ID。
3. 选代理模式：**固定用户**只发 `tenant_id`；**白名单用户**需要再填 `subject_type` 与 `subject`（`erp_user` 还要 `data_center_id`）。右下的「令牌请求体预览」会显示实际要发的内容。
4. 想以后复用就点「保存为常用」，下拉即可切换。
5. 点「获取令牌」，成功后关掉抽屉，直接提问。

输入框下方可以选择智能体、模型和工具（不选工具表示不限制），右侧 `↻` 重新拉取这三个列表。

## 文件结构

```
start.js            启动器：挑空闲端口 + 开浏览器（跨平台）
启动-Windows.bat     Windows 双击入口
启动-macOS-Linux.sh  macOS / Linux 入口
server.js           本地服务：静态托管 + /api 反向代理
public/index.html   前端页面（单文件，样式与脚本都内联）
```

## 说明

- 页面里填的「服务地址」会通过 `X-Target` 请求头带给本地服务，因此可以在测试/生产环境之间随时切换，不必重启。
- App Secret 只保存在浏览器 localStorage，命中签名也在浏览器本地完成；Node 服务只做透明转发，不读取、不落盘。
- 历史会话保存在浏览器 localStorage。服务端没有「列出会话」的接口，所以换浏览器或清缓存后本地记录会丢，但服务端上下文仍在——只要还记得 `session_id`，仍可继续那条会话。
- **断点续查**：每次发起对话都会把 `task_id` 记进该会话的本地记录。中途关页面、断网或进程被杀，下次打开那条会话时会自动用 `task_id` 轮询终态、把回答补上（这类会话在左侧历史里标「未完成」）。若当时连接没配好，会显示「继续查询结果」按钮，点一下即可。
- **轮询上限 3 次**：对话结果与断点续查都最多查 3 次（每次间隔 2–3 秒）。用尽时如果 SSE 还连着就继续等流；否则收尾并保留「未完成」标记，稍后可再点该会话继续查询。
- **调试看板**（左下角进入，默认隐藏）：按顺序记录签发令牌、建会话、建 SSE、发对话等每一步的请求地址、请求头、请求体与响应，可按「当前会话 / 全部会话」过滤。记录持久化在本机（保留 24 小时内、最多 150 条），刷新页面不丢；令牌与签名默认打码，勾选「显示令牌」才显示明文。SSE 那条会给出事件数、首末事件跨度和「逐条流式 / 批量下发」的判断，用来定位是不是服务端在缓冲。
- 遇到 `502 PROXY_ERROR`：说明本地服务连不上目标环境，先确认网络与「服务地址」。
- 只监听 `127.0.0.1`，不对局域网开放。若确实需要，设置 `HOST=0.0.0.0`（不建议，密钥页面就在里面）。

## 数据存在哪 / 怎么清除

所有数据**只存在浏览器 localStorage**，服务端不写任何文件。localStorage 按来源隔离，`http://127.0.0.1:3000` 与 `http://127.0.0.1:3001` 是**两份互不相通的数据**（换端口就等于换了一份）。

| 键 | 内容 | 是否敏感 |
|---|---|---|
| `lingee.presets` | 常用连接配置：服务地址、App ID、租户、代理模式与用户标识、**App Secret 明文** | 是 |
| `lingee.activePreset` | 当前选中的配置 id | 否 |
| `lingee.sessions` | 历史会话：标题、消息、`pendingTask` | 含对话内容 |
| `lingee.debug` | 调试看板记录，保留 24 小时 / 最多 150 条。令牌、签名、Nonce 以及响应体里的 `access_token` **写入时即打码**（形如 `Bearer lta_SE••••••3456`） | 已打码 |

清除方式：

1. **一键全清**：连接设置 → 本机数据 →「清除全部本机数据」，删除以上四项并刷新页面。
2. 分类清除：常用配置「删除当前」、左侧历史「清空」、调试看板右上「清空」。
3. 手工：F12 → Application → Local Storage → 选中 `http://127.0.0.1:端口` → 删除；或在 Console 执行 `localStorage.clear()`。

App Secret 必须明文保存在本机才能完成 HMAC 签名，因此：**公用电脑用完请执行「清除全部本机数据」**；不要把浏览器配置文件整体拷给别人。

## 已知限制（本版）

| 限制 | 现状 | 影响 |
|---|---|---|
| 单会话单轮 | 全局只有一个活跃轮次，`S.busy` 一把锁 | 会话 A 在跑时，会话 B 发消息会被忽略（无提示） |
| 切换会话会中断流 | 切走时关闭 SSE、清空当前轮次 | 已流出的半截文本不落库；切回来靠 `task_id` 续查拿终态，看不到过程 |
| 不支持多会话并行 | 单条 SSE 连接、单个轮次槽位 | 需要同时跑多个会话时只能排队 |
| 轮询是「并跑」不是「兜底」 | 提交对话后立刻轮询 3 次 | SSE 正常时多打 3 次接口；SSE 断时额度可能已耗尽 |
| 多标签页会互相覆盖 | localStorage 共享，无互斥 | 两个标签打开同一会话时 `pendingTask` 可能互相覆盖 |

下一版计划：轮次注册表（按会话）、每会话一条 SSE、后台收流与未读提示、并行上限 3、轮询改为事件驱动的兜底、令牌重签加单飞锁。
